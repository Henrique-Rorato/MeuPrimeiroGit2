Qual a diferença entre Working Directory, Staging Area e Repository?
-
Working Directory: é a pasta onde você está trabalhando no arquivo localmente.
Staging Area: é a área onde você coloca os arquivos que deseja incluir no próximo commit.
Repository: é o histórico do projeto no Git, onde os commits ficam salvos.

Qual a diferença entre git commit e git push?
-
git commit: salva as alterações localmente no histórico do projeto.
git push: envia esses commits para o repositório remoto, como GitHub.

É possível realizar vários commits antes de executar um git push?
-
Sim. É possível fazer vários commits locais antes de enviar para o remoto.

Por que é interessante realizar commits pequenos e descritivos
-
facilita a revisão do histórico;
ajuda a entender o que mudou em cada etapa;
reduz o risco de perder alterações importantes;
torna mais fácil voltar atrás se algo quebrar.

O que acontece com os commits locais quando ainda não executamos o git push?
-
Eles continuam existindo apenas no seu computador, no repositório local. Eles não vão para o GitHub até você executar o git push.

Como verificar, pelo GitHub, se os commits foram enviados corretamente?
-
acessando o repositório no GitHub;
olhando a aba “Commits” ou a página principal do projeto;
e confirmando se os últimos commits aparecem no histórico.

Como confirmar se o commit foi enviado corretamente?
-
Use git status, se aparecer algo como “Your branch is up to date” ou “nothing to commit”, normalmente está tudo certo.
